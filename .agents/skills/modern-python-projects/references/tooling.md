# State-of-the-art Python tooling

Use one integrated, fast toolchain for new Python projects.

## Python

Use the current stable Python release available through `uv`. Record it in `.python-version`; let `uv init` set `project.requires-python` from the selected interpreter.

Do not copy a Python version from this reference. Resolve it when creating the project so the skill does not become stale.

## uv

`uv` owns the complete project workflow:

- Python installation and selection
- project initialization
- virtual environment
- runtime and development dependencies
- lockfile and deterministic synchronization
- command execution
- package builds

Canonical commands:

```bash
uv init ...
uv add <runtime-dependency>
uv add --dev <development-dependency>
uv lock --check
uv sync --locked
uv run <command>
uv build
```

Do not duplicate this workflow with another package or environment manager.

## pyproject.toml and uv_build

Use `pyproject.toml` for:

- project metadata
- Python requirement
- dependencies and development dependency groups
- build system
- entry points
- Ruff, pytest, and project-specific `ty` configuration

For libraries and packaged applications, keep the `uv_build` backend generated by current stable `uv init`. Do not introduce backend selection into ordinary initialization.

## Ruff

Ruff owns formatting, linting, import sorting, Python-upgrade checks, and common bug-pattern checks.

Use this focused ruleset:

- `E4`, `E7`, `E9`: syntax and high-signal pycodestyle errors
- `F`: Pyflakes
- `I`: import sorting
- `UP`: modern Python syntax
- `B`: bug-prone constructs
- `SIM`: needless complexity

Do not use `select = ["ALL"]`. More rules are not automatically better.

## ty

Use `ty` as the single static type checker. Type public functions, application boundaries, and meaningful domain values from the beginning.

Canonical command:

```bash
uv run ty check
```

Start without checker-specific configuration. Add narrow settings only in response to concrete source behavior.

## pytest

Use pytest with strict configuration and strict markers. Begin with a real interface test rather than a placeholder assertion.

Canonical command:

```bash
uv run pytest
```

Plugins are requirement-driven, not baseline tooling.

## CI

CI executes the local contract from a locked environment:

```bash
uv sync --locked
uv run ruff check .
uv run ruff format --check .
uv run ty check
uv run pytest
uv build
```

Skip `uv build` only for a standalone script. Use the CI platform’s maintained `uv` installation integration. Do not cache `.venv` manually.

## Deliberately absent from the baseline

Do not add these during ordinary initialization:

- alternate package managers or build backends
- alternate formatters, linters, or type checkers
- requirements files
- task runners
- local hook frameworks
- coverage gates
- documentation-site generators
- architecture frameworks or folder tests
- release automation

Add new tooling later only when a concrete project requirement exists.
