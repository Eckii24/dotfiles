# Gondolin sandbox

Dormant unless `--sandbox` or exact `PI_SANDBOX=gondolin`. Active TUI/print/json routes built-in file and shell surfaces into one Gondolin VM per Pi process. Every sandboxed bash and `user_bash` command is rewritten guest-side by the verified RTK 0.43.0 binary before execution; host `rtk-rewrite` deliberately skips sandboxed calls. Host guardrails deliberately skip all sandboxed calls: the guest workspace is intentionally unrestricted within its mounts. RPC activation fails closed. Default host exposure: current workspace RW at `/workspace`; network deny by default; no credential mounts.

Sandboxed child Pi processes inherit `PI_SANDBOX=gondolin` plus any validated session-only startup policy; the inherited policy is bounded, revalidated in every child, and never logged by Herdr. Profile-restricted tools remain absent; ownership validation ignores absent routed tools but fails closed for any present routed tool owned by another extension. Backend resolves effective policy `backend`, then `GONDOLIN_VMM`, then `qemu`; only `qemu` and `krun` are accepted. `/sandbox` reports resolved backend and compact navigation.

Sandboxed `grep`, `find`, and `ls` bound output inside guest before VM transfer, report result/byte truncation, and return paths relative to requested root for later `read`. `grep` includes hidden files while respecting gitignore. `find` uses Git's ignored-file rules inside Git worktrees; outside one, bundled `find` supplies glob matching without `.gitignore` interpretation.

Commands use one hard-breaking parser: `/sandbox` (no args) shows status plus compact navigation; `/sandbox status`; `/sandbox help`; `/sandbox policy show`; `/sandbox mount help`; `/sandbox mount ro|rw help`; `/sandbox network help`. Policy changes run only from a normal idle TUI prompt, never during questionnaire or agent turn. Project scope is default when trusted; project policy requires Pi trust and full-section approval. Mount grammar: `/sandbox mount ro|rw add HOST [--guest GUEST] [--required] [--scope global|project]` (for example, `/sandbox mount ro add "/absolute/path/reference docs" --guest /reference --required`) or `/sandbox mount ro|rw remove HOST_OR_GUEST [--scope global|project]`; remove matches exact normalized host or guest path. Network grammar is `/sandbox network allow|deny add|remove HOST_PATTERN [--scope global|project]`. HOST and GUEST must be absolute. Pi command parsing does not shell-expand `~` or variables. Use explicit global scope only for needed dependency mounts: `/sandbox mount ro add /absolute/path/.pi/agent/packages/my-package --guest /pi-package --scope global` and `/sandbox mount ro add /absolute/path/.pi/agent/agents/my-agent --guest /agent/my-agent --scope global`; never mount whole agent directory. Commands write policy only and apply next Pi session/restart.

Startup flags apply only to the current sandbox session tree, never mutate settings, and require explicit `--sandbox`: `pi --sandbox --sandbox-mount-ro /absolute/reference --sandbox-network-allow api.example.com`. Each of `--sandbox-mount-ro`, `--sandbox-mount-rw`, `--sandbox-network-allow`, and `--sandbox-network-deny` accepts one scalar value. Because Pi extension flags are not repeatable, pass a JSON array for multiple values: `pi --sandbox --sandbox-mount-ro '["/absolute/a",{"hostPath":"/absolute/b","guestPath":"/deps","required":true}]' --sandbox-network-allow '["api.example.com","*.example.org"]'`. Mount array entries are strings or strict `{hostPath, guestPath?, required?}` objects; network arrays contain strings. Startup host paths must already exist. Malformed, oversized, conflicting, or invalid startup input fails closed before VM creation.

Default image: `pi-agent-work:0.12.0`. On first sandbox startup, extension builds host-native bundled image, imports it into Gondolin local image store, then starts it. First build needs network access on a trusted machine; if SSL/TLS breaks, transfer Gondolin image store instead. Custom policy images are never built by extension. Build/status failures show exact reason in footer and `/sandbox`.
